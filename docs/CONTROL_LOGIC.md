# Логика управления и причины решений

## Последовательность задачи

Фактическая реализация — `TaskPlanner` в `src/active_scan/control.py`.

| Этап | Действие | Условие продолжения |
|---|---|---|
| READ_STATE / PLAN_TASK | проверить готовность библиотеки, геометрию раскрытия и достижимость захвата | есть допустимый захват и маршрут |
| MOVE_PREGRASP / APPROACH | перейти к предзахвату и выполнить декартово сближение | limits, tracking и collision checks проходят |
| CLOSE_GRIPPER | закрыть и дождаться допустимой обратной связи | завершение закрытия в пределах timeout |
| VERIFY_GRASP | в contact-профиле сделать короткий пробный подъём | объект действительно движется с инструментом |
| LIFT | поднять на рабочую высоту | нет недопустимого смещения удержания |
| PLAN_VIEW_SEQUENCE | выбрать и упорядочить достижимые наблюдения | достаточный прирост информации |
| MOVE_TO_VIEW / SETTLE / CAPTURE | перейти, стабилизировать и проверить кадр | масштаб/видимость/качество проходят |
| UPDATE_COVERAGE | обновить фактически полученное покрытие | только принятый кадр даёт вклад |
| MOVE_PREPLACE / REORIENT / PLACE | развернуть и опустить на опору | путь и укладка допустимы |
| RELEASE / VERIFY_PLACEMENT / RETREAT | отпустить, проверить опору и отвести руку | объект установлен корректно |
| PLAN_REGRASP | повторить захват с другой стороны при необходимости | доступен второй захват |
| FINISH / DONE | вернуть объект на стол и руку home | целевой результат подтверждён |
| RECOVERY / FAILED | контролируемо остановиться, сохранить причину и диагностику | успех не объявляется |

Переворот с освобождением на столе нужен, чтобы открыть ранее закрытую грань.
Он не требует от пятиосевой руки произвольной шестимерной ориентации в воздухе.
По умолчанию симуляционный полный сценарий проверяет перехват; `--single-grasp`
разрешает остановить наблюдения после первого захвата, если coverage достаточен.

## Планирование и рабочее время

Большой поиск захватов/ракурсов выполняется в `prepare_library.py`. Библиотека
связывается с конфигурацией, XML, скомпилированными meshes, массами/инерциями,
ограничениями и кодом геометрического планирования. Важная особенность:
в XML есть абсолютные пути к assets, поэтому после переноса checkout cache
не считается автоматически переносимым. На новой машине нужна подготовка.

Во время цикла номинальные данные дают короткий список. FK/IK, путь,
столкновения и видимость выбранных поз проверяются по текущему состоянию.
Проверенные пути могут повторно использоваться, пока консервативная оценка
смещения остаётся внутри сохранённого запаса; иначе они проверяются снова.
Это дискретные проверки, не доказательство непрерывной collision freedom.

Оценка ракурса в исходном планировщике учитывает прирост coverage и цену
движения. Для режима `time_normalized_gain` используется отношение gain к
оценке времени движения плюс settle time. Обход порядка минимизирует
оценённую длительность следующего перехода. Это геометрическая эвристика;
она пока не гарантирует observability нового RGB-D localizer.

Историческая B-серия сократила рабочее планирование примерно с 28.16 до
3.36 с при движениях около 38 с. Это отдельные измерения, не аппаратный такт.
Текущая sensor preflight отвергает прежние шесть ракурсов при запасе маски
4 мм. Их нужно согласовать с локализацией частично видимого куба, а не
переносить прежнее coverage в утверждение об аппаратной реконструкции.

## Траектории и регулятор

Для отдельного перехода используется quintic smoothstep:

```math
s(u)=10u^3-15u^4+6u^5,\quad q(t)=q_0+s(t/T)(q_1-q_0).
```

Длительность учитывает максимумы скорости и ускорения. Декартовы IK-узлы
соединяются C2 spline с общей временной параметризацией: это геометрические
узлы одного движения, а не отдельные остановки сервопривода. Проверяются
кривизна, limits и дискретный путь. Изменения ускорений не выдаются за
источник ранее измеренного ускорения цикла: профили ограничений сохранены.

При включённых velocity/bias feedforward позиционная уставка эквивалентна:

```math
q_{cmd}=q_{ref}+\frac{K_v}{K_p}\dot q_{ref}+\frac{b(q,\dot q)}{K_p},
```
```math
\tau\approx K_p(q_{ref}-q)+K_v(\dot q_{ref}-\dot q)+b(q,\dot q).
```

Эквивалентность действует до ограничения уставки и усилия. Компенсация
проходит через ограниченный actuator; не используется неограниченная внешняя
сила. Профили gains для пустой и нагруженной руки заданы в конфигурации.
Фактические tracking/speed/collision checks выполняются в Executor.
Этот MuJoCo-регулятор не является готовым аппаратным драйвером сервоприводов.

## Захват без дополнительных датчиков

Остановка гриппера в промежуточном положении — признак препятствия, а не
доказательство захвата. В factory contact-профиле используется position stall
и пробный подъём 10 мм. Базовые пороги: подъём объекта ≥6 мм, относительное
смещение ≤4 мм, угол ≤0.15 rad. Это настройки, требующие физической проверки.

В hardware-интерфейсе движение объекта должно измеряться существующей D455.
Поза инструмента берётся из синхронизированной обратной связи. Если движется
только инструмент, тест обязан завершиться неуспехом. При заданных bounds
проверяются нижняя граница подъёма и верхняя граница slip, включая ошибку
инструмента. Недостаточная точность даёт `GRASP_EVIDENCE_UNCERTAIN`.

Контакты MuJoCo допустимы как диагностика C-симуляции и не объявляются
аппаратными контактными сенсорами. Source `simulation_ground_truth` в старом
FSM остаётся явно обозначенным. Физический контактный захват не подтверждён.

## Правило отказа

Collision, tracking abort, недостижимость, некачественный кадр, потеря/старение
измерения, смена object identity или чрезмерный error budget не превращаются
в успех. Executor пытается выполнить проверенное торможение, затем hold
fallback при невозможности безопасного brake path. Это программная логика
симуляции, не сертифицированная emergency-stop система реального стенда.

`PREDICTED` — старое удержанное состояние с растущей неопределённостью.
Оно не подтверждает захват, не увеличивает измеренное покрытие и не идёт в TSDF.
При снятии допуска hardware observer физическое движение должен останавливать
будущий аппаратный адаптер; нынешний snapshot не содержит полного такого драйвера.
